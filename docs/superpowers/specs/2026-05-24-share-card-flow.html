🎀 공유 카드 흐름
플레이리스트 → 카드 → 유입 (위에서 아래로)
1단계 · 공유 만들기
플리 주인이 공유 링크를 발급받는 단계
1
🧑 주인 → 📱 앱
[공유] 버튼 클릭
2
📱 앱 → 🍳 백엔드
공유 코드 발급 요청
POST /api/playlists/{id}/share
3
🍳 백엔드 → 📒 DB
share_code 발급/조회 (처음 한 번만)
4
🍳 백엔드 → 📱 주인
링크 복사 / 이미지 저장 버튼 표시
shareUrl = /p/{code}
2단계 · X에 올리기
주인이 링크를 트윗에 붙임
5
🧑 주인 → 🐦 X(트위터)
공유 링크를 붙여서 트윗
https://…/p/{code}
3단계 · 봇이 미리보기 카드 만들기
사람이 아니라 트위터 로봇(크롤러)이 먼저 와서 미리보기를 만듦
6
🤖 크롤러봇 → 🚪 nginx
링크 구경하러 옴 (이름표: 봇)
GET /p/{code} · UA=Twitterbot
7
🚪 nginx → 🍳 백엔드
🔀 "봇이네!" → 안내문 경로로 보냄 (OG SSR)
/share/p/{code}
8
🍳 백엔드 → 🐦 X
대표 사진 이름표가 박힌 안내문 HTML
og:image = …/card.png
9
🐦 X(봇) → 🍳 백엔드
그 카드 사진 줘!
GET …/card.png
🗄️ 백엔드: "이 카드 서랍(캐시)에 있어?"
10
없으면 (캐시 미스)
DB에서 카드 데이터 모음 → 🎨 화가에게 그리기 요청 → 사진 받아 서랍에 저장
POST /render (HTML → PNG 찰칵)
— 또는 —
10
있으면 (캐시 히트)
서랍에서 바로 꺼냄 (빠름, 다시 안 그림)
11
🍳 백엔드 → 🐦 X
card.png 전달 → 미리보기 카드 표시 ✨
4단계 · 유입 루프
팔로워가 카드를 보고 들어와서 가입 → 또 공유 (반복!)
12
🧒 팔로워
타임라인에서 예쁜 카드를 봄 → 링크 클릭
13
🧒 팔로워 → 🚪 nginx
🔀 같은 링크지만 이름표가 "사람" → 진짜 사이트(SPA)를 줌
GET /p/{code} · UA=브라우저 → index.html
14
📱 앱 → 🍳 백엔드
공개 플리 데이터 요청
GET /api/share/playlists/{code}
15
📱 앱 → 🧒 팔로워
공개 플리 화면 + [가입하기] 버튼
16
🧒 팔로워
가입 🎉 → 이제 이 사람이 또 플리를 공유 (루프!)
💡 핵심 한 줄
같은 주소 /p/{code} 인데,
손님 이름표(UA)가 봇이면 → 안내문(OG),
사람이면 → 진짜 사이트(SPA) 로 갈라보내는 게 설계의 심장이에요.
